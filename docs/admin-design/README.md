# Реализация принятого оформления админки

Источник функций и данных — `engine/templates/admin_dashboard.html` и существующие
обработчики `engine/views.py`. Визуальное направление принято пользователем по
`admin-concept-pattern-hover.html` 9 сентября 2026 года. Демонстрационные данные
и обработчики концепта в приложение не переносятся.

## Граница изменения

`engine/static/css/admin-concept.css` загружается после существующих стилей.
Он подключает отдельные стили инфраструктуры, клиентских и остальных разделов и переносит
размеры, типографику, навигацию, таблицы, диалоги и компоновку карточек из
концепта: Manrope, боковая панель 202 px, отступ контента 26 px, открытая полоса
KPI. Точные значения перечислены в [DESIGN.md](DESIGN.md).

Операции, API-привязки и проверки роли сохраняются. Изменения шаблона включают
подключение стилей, оформление
названия бренда, представлением параметров карточки конфига, сводкой и шестью
вкладками пользователя, полями и композицией рассылок/промокодов, таблицей
установок, идентификацией серверов и отрисовкой графиков: коридор p25–p75,
шкала выручки, типографика легенд/осей и фактическая доля ступени воронки.
Фильтры трёх страниц привлечения расположены перед графиками, редактор
шаблонов — рядом со списком. Заголовок отражает активную вкладку, счётчики
меню вычисляются из доступных вкладок. Локальная прокрутка таблиц,
редакторы, раскрывающиеся блоки и мобильное меню используют существующую логику.
Сопоставление конкретных блоков:
[клиентские разделы](customer-mapping.md),
[инфраструктура](infrastructure-mapping.md).

Для Win-back перенесена сама структура редактора: одна карточка со строками
«подпись — значение», единая кнопка под ней. Сохранены восемь реальных ключей,
а не четыре демонстрационных поля концепта. Технические описания, типы,
источники и даты собраны в раскрывающемся блоке; там же можно подготовить
сброс конкретного override и отменить его до сохранения. Изменён только
обработчик этой группы (`admin-winback-settings.js`); остальные runtime-формы
продолжают использовать исходный обработчик.

Единое сохранение использует существующий `POST action=save/delete,key,value`,
не создаёт batch API и не обещает атомарность. Валидация всех изменённых полей
происходит до первого POST, подтверждённые ключи снимаются с очереди, при
ошибке оставшийся ввод сохраняется. Потерянный ответ проверяется чтением
того же ключа; автоматического rollback нет. Неизвестный effective default
остаётся пустым значением env/default. Соседние bot/user-notify/payment
проверены по коду; их контракты и логика остаются прежними.

`tests/admin_winback_browser.cjs` проверяет композицию, доступность всех ключей,
валидацию, сброс/отмену, частичный сбой, повтор и неопределённый сетевой исход.
Все запросы перехватываются локально, никаких записей в БД или запусков
уведомлений тест не выполняет.

каждой операции с production-сервисами.

## Проверка

```sh
.venv/bin/python tests/render_admin_fixture.py /tmp/mi-admin-review
node tests/admin_concept_browser.cjs
node tests/admin_tspu_selection_browser.cjs
node tests/admin_concept_fidelity_browser.cjs
node tests/admin_tabs_browser.cjs
node tests/admin_customer_concept_browser.cjs
node tests/admin_customer_details_browser.cjs
node tests/admin_shell_concept_browser.cjs
node tests/admin_campaign_concept_browser.cjs
node tests/admin_infrastructure_concept_browser.cjs
node tests/admin_sections_concept_browser.cjs
```

Нужны Django, Playwright и установленный Chrome. `NODE_PATH` при необходимости
указывает на каталог установленных модулей. `ADMIN_FIXTURES` меняет папку фикстур
и скриншотов. Рендер фикстур использует шаблон из Git HEAD как контрольный и
проверяет, что исходный код вне перечисленных изменений представления сохранён.
Браузерный тест сравнивает доступные элементы исходного и обновлённого
оформления для admin/marketer/support, тёмной/светлой темы, мобильного/настольного
экрана. Дополнительно проверяет редакторы, версии скрипта и мобильное меню.
Ответы API перехвачены; ошибки сервисов показаны тестовыми состояниями.
Тест также проверяет ширину поля Telegram ID и отсутствие горизонтального
переполнения страницы рассылок на мобильном экране.
Тест не отправляет сообщения, не создаёт установки и не меняет подписки.

Отдельная проверка ТСПУ использует три тестовые проверки и восемь ширин
от 320 до 1440 px, включая границы 640/641 и 760/761 px, в обеих темах.
Она проверяет зазор между чекбоксом и «Все», отсутствие наложения на IP,
выравнивание колонки, выбор всех строк, частичный выбор и сброс.
Запросы изменения данных блокируются и считаются ошибкой теста.

Проверка соответствия концепту проверяет вычисленные размеры, шрифты, цвета,
навигационные иконки и KPI; снимает все разделы и подразделы на экранах
1440 и 390 px. Ключевые клиентские и инфраструктурные разделы используют
наполненные фикстуры. Для остальных API допустимы явно обозначенные состояния
ошибки, поэтому снимки не заменяют проверку всех вариантов данных.
На графике паттернов проверяются точные значения подсказки текущего и будущего
часа. Если задан `ADMIN_REFERENCE_HTML` с путём к принятому концепту, рядом
сохраняются 16 эталонных снимков восьми страниц. Результаты находятся в
`/tmp/mi-admin-review/fidelity` по умолчанию.

Отдельный тест вкладок проверяет четыре раздела на пяти ширинах в обеих темах:
подчёркивание по ширине текста, отсутствие декоративных иконок, перенос строк,
все существующие переключения и видимый клавиатурный фокус.

Тест карточки клиента сравнивает сводку с исходным `cu-summary` концепта при
одинаковых данных и ширине контента: размеры, относительные координаты,
шрифты, отступы, цвета, вкладки и поля действий. Проверяются 1440/1100/390 px,
светлая тема, исходные доступы admin/marketer/support, истёкшая подписка,
выключенный автоплатёж, управляемый/ручной лимит и недоступность RWMS.
Пары снимков и отчёт сохраняются в `customer-concept` внутри папки фикстур.
Исходные подробные пояснения бизнес-операций сохранены, поэтому их переносы
и высота могут отличаться от сокращённых демонстрационных текстов концепта.

Проверка вложенных разделов клиента использует наполненные ответы: RUB/USD/EUR
и ожидающий платёж, раскрытие строки, четыре поля таймлайна, расхождения и
отсутствие подписки в панели, граф и блокировка рефералов, история доставки
сообщений. Проверяются desktop/mobile и права управления рефералами. Все
запросы изменения данных заблокированы и считаются ошибкой проверки.

Другие сервисы: изменений контрактов, моделей, gRPC, платежей, уведомлений,
Remnawave или жизненного цикла подписок нет. Изменений соседнего кода и миграций
не требуется. Production-интеграционные операции в этой проверке не выполняются.

Для точной сверки задайте `ADMIN_REFERENCE_HTML` — путь к принятому
`admin-concept-pattern-hover.html`. Shell-проверка сравнивает меню при ширинах
390/700/701/760/1024/1440, все заголовки, счётчики и мобильное меню.
Campaign-проверка сравнивает 126 компонентов на 1480/1100/390 px, включая
режимы кнопок, эффекты промокодов, реестр, когорты и нулевые значения.
Инфраструктура проверяет шесть наполненных состояний на 1440/390 px;
`ADMIN_ASSERT_CONCEPT=1` включает строгую сверку CSS,
`ADMIN_INFRA_CASES=inf-provision` ограничивает прогон таблицей установок.
Sections-проверка покрывает 25 представлений админки и открытый/закрытый тикет;
`ADMIN_SECTIONS_CONFIRM=1` проверяет только исправленные группы.
Проверки снимают пары фактического и эталонного интерфейса, сохраняют JSON-отчёты
в подкаталогах `shell-concept`, `campaign-concept`, `infrastructure-fidelity`
и `sections` папки фикстур. Отдельная страница тикета сохраняет прежний маршрут,
переписку, вложения и формы, используя тот же шрифт и поверхности сообщений.

Содержательные отличия от демонстрации сохраняются намеренно: дополнительные
реальные поля и подробные пояснения не вырезаются. На мобильном доступны
предпросмотр рассылки и подсказки промокодов: побочный эффект общего правила
`aside { display: none }` из концепта не переносится. Эти отличия не являются
обоснованием для иной сетки, типографики или цвета основных компонентов.

## Найденное существующее несоответствие

В исходном шаблоне роль marketer видит пункт «Привлечение», но соответствующий
`panel-acquisition` рендерится только для полного администратора. Сравнительный
тест фиксирует эту особенность обеих версий. Изменение авторизации и видимости
по ролям в CSS-реализацию не включено.
